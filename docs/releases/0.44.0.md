# Findroid 0.44.0-preview — Resume saved copies

Large local copies can retain durable checkpoints when their destination supports safe recovery. In **Actions → Transfers**, choose **Review saved copy…** to inspect the source, destination and saved amount, then choose **Resume saved copy**. A fresh review is required after every restart; closing the review starts no work.

Findroid checks the complete source and saved prefix, checks them again before execution, copies the remaining bytes, and reads the whole working copy back before publication. Any unchecked tail is disclosed and recopied. Checked saved bytes and newly copied bytes have separate counts. The original interrupted history is kept, and the resumed operation gets its own transfer entry.

**Discard saved bytes…** has a separate confirmation and removes only reviewed private working data. If Android stopped the copy while it was finishing, the destination is reviewed separately and is preserved during cleanup. Clearing finished history keeps transfers that still own saved bytes.

The first increment supports individual local files of at least 8 MiB, with a checkpoint every 4 MiB. Destination storage must share a filesystem with private working storage and pass atomic no-replace rename and directory-sync probes. Workspace is the main supported destination. Providers, folders, moves, replacements and unsupported storage use the existing restart behavior. See the [recovery guide](../PARTIAL-COPY-RESUME.md).
