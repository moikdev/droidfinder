# Findroid 0.45.0-preview — Undo after reopening

Supported local Undo and Redo can now survive reopening Findroid. Open **More → Recent actions…** to see what can be undone, the affected paths and whether each action is **Saved for restart** or **This session only**. Reopening starts no file operation.

The saved scope includes new files and folders, copies, moves, renames, grouping, Trash and restoration from Findroid's own Trash on supported local storage. Actions stay in order across both panes and app windows. Provider operations, replacements, organization callbacks, links, special files and oversized histories stay in the current session. An older action behind one of those boundaries is never promoted into the saved list using newly collected file identities.

Before Undo or Redo, Findroid checks saved file identities, content fingerprints, parent paths and exact destinations. An edit, recreated file, redirected parent, occupied name or changed Trash mapping stops the action. Native publication keeps occupied destinations. If an operation or metadata save may have stopped partway through, **Saved Undo needs review** keeps the list read-only.

**Reset Undo list…** opens a separate review. **Keep Undo list** preserves the exact record. Confirming reset retires the current references and preserves the complete old record separately in app storage; documents and Trash stay in place. Every named action and confirmation scrolls into view on narrow tablet windows and at enlarged text sizes. No permanent toolbar control is added.

The private saved list is bounded by action count, step count, tracked roots, proof entries and serialized bytes. Retiring a reference never deletes a document. See the [persistent Undo guide](../PERSISTENT-UNDO.md) for supported storage, checks and recovery behavior.

Release acceptance is in progress. The public download remains 0.44 until final native, optimized-build and public OTA acceptance is complete. Proposal 42 remains in progress.
