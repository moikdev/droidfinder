## Drag folders into Favorites

**Findroid 0.31.0 preview** adds a named folder-pinning target under the sidebar's Favorites heading.

Hold a **folder icon**, drag it onto **Drag folders here**, and release when it says **Release to add**. With a mouse, drag the icon directly. Select several folders and hold the labeled **Drag** control to pin them together.

- Favorites save shortcuts. The original folders stay where they are, and the shortcuts survive restarting the app.
- Dropping an already-favorited folder again keeps the favorite. Parent-path aliases do not create duplicate entries.
- Read-only connected folders can be pinned while their storage access remains available.
- File-only and mixed file/folder drops are rejected together, with an explanation. Folders are rechecked before saving.
- Cancellation saves nothing, and pinning restores any temporary folder navigation used during the drag.
- Existing sidebar folder rows still accept copy/move drops into those folders, with normal Undo.

This release also publishes **72 concrete next-improvement proposals**, prioritized around sidebar management, clearer everyday actions, setup backup, search, tablet input, and network locations. See `docs/NEXT-IMPROVEMENTS.md` in the source.

## Install or update

From **0.30**, open **More → App updates**, check for this version, download it, and confirm the Android installation. Or download **Findroid-0.31.0-preview.apk** below and install it over the existing app.

From **0.29**, install this APK once over the app. The repository rename broke that older version's update source; the corrected updater was introduced in 0.30. Existing files and settings are retained when installing a same-signed newer version over Findroid.

Android 11 or newer is required. This is an optimized, development-signed preview. The unsigned APK is for developers. Source, actual tablet screenshots, checksums, the update manifest, build information, and a validation archive accompany this release. Physical-tablet and third-party provider compatibility remain separate validation work.
