## Recover a saved workspace when storage has changed

**Findroid 0.34.1 preview** reviews missing tab destinations before opening a saved layout and lets you repair the locations that need attention. It also fixes the activity-replacement crash found during 0.34.0 public OTA acceptance: an outgoing screen can still read its own recovery controller after its pane leaves the live registry. 0.34.0 was withdrawn from the update feed.

- Open a named layout from **More → Workspaces…**. Available layouts open immediately. A missing folder identifies its pane and tab; tabs that share the same destination share one choice.
- Reconnect storage and check again, or choose a replacement folder. Read-only destinations are supported. Provider identifiers come from the selected folder.
- Choose **Open once** to leave the saved workspace unchanged, or **Save repairs and open** to remember the chosen repairs in that workspace.
- Working tabs keep their state. Repaired tabs keep their pins, queries and filters; pane views, ratio, order and active-pane choices stay in place. Unrelated missing back-history entries and a hidden secondary pane do not block an available layout.
- A Smart Folder with an offline search root can use a replacement folder for the saved tab while keeping its filters and extra query. Its shared definition stays unchanged.
- Explicitly choose whether to keep still-unavailable destinations. Findroid does not silently substitute a different folder or create missing content.
- Final actions recheck availability, the saved layout and relevant search definitions. Saving waits for file operations, guards the shared writer, and atomically publishes before opening. A failed save retains the original in-memory layout and still offers Open once; changed-on-disk or future-format catalogs are preserved.

Your files, Favorites, tags, collections and other saved layouts stay where they are. [Workspace recovery guide](../WORKSPACE-RECOVERY.md). Whole-setup migration remains available through [setup backup and restore](../SETUP-BACKUP.md).

This implements proposal **18**. **17 of the 72 authorized proposals are implemented; 55 remain open or partial.** Physical tablets, TalkBack, removable-drive removal and actual third-party providers still require separate acceptance in the [tracker](../IMPROVEMENT-TRACKER.md).

## Install or update

From **0.30 or newer**, use **More → App updates** and confirm Android's installation prompt. You can also install **Findroid-0.34.1-preview.apk** over your existing app. Keep the app installed during upgrades to retain its private Workspace and settings. Version 0.29 needs one manual install because it predates the repository-address fix.

Android 11 or newer is required. This is an optimized, development-signed preview; the unsigned APK is for developers. The release includes source, actual Android screenshots, checksums, the OTA manifest, build information and a whitelisted validation archive.

Local validation passes: **360 JVM tests**, **133/133 native cases on each API30/API36 tablet emulator**, optimized 0.33 → 0.34 upgrade, real replacement-folder selection, Open once, reviewed saved repair, restart and reopen, original-byte/preference preservation, font scale 1.6, and three repeated task replacements on each optimized build with the same app process. Debug/preview/unsigned builds pass; lint has zero errors, 143 warnings and 11 hints. Public downloads and OTA upgrades from both 0.33 and the withdrawn 0.34 will be recorded after publication.
